# 🎤 Настройка Wake Word "Hey Eva"

## Обзор

RobotEva использует **OpenWakeWord** для обнаружения wake word **"Hey Eva"**. Это позволяет роботу "проснуться" и начать слушать команды только при обращении к нему.

## ⚙️ Текущая конфигурация

Wake word уже настроен на **"Hey Eva"** в конфигурации:

```yaml
ai:
  wake_word:
    # Если true, после wake word требуется дополнительное "wake up"
    require_wake_up: false  # "Hey Eva" сразу активирует прослушивание

    openwakeword:
      mode: onnx  # Используем кастомную ONNX модель
      hey_eva_onnx_path: /home/pi/Projects/RobotEva/models/openwakeword/hey_eva.onnx
      threshold: 0.75
      device_index: 0
```

## 🎯 Как работает активация

### Простая активация (рекомендуется):
1. Пользователь говорит: **"Hey Eva"**
2. Робот обнаруживает wake word
3. Робот сразу начинает слушать команду
4. Пользователь произносит команду

### Активация с "wake up" (опционально):
1. Установите `require_wake_up: true` в config.yaml
2. Пользователь говорит: **"Hey Eva wake up"**
3. Робот проверяет наличие "wake up"
4. При успехе начинает слушать команду

## 🛠️ Устранение проблем

### Wake word не обнаруживается:

1. **Проверьте микрофон:**
   ```bash
   # Тест микрофона
   arecord -d 5 -f cd test.wav
   aplay test.wav
   ```

2. **Проверьте device_index:**
   ```yaml
   openwakeword:
     device_index: 0  # Попробуйте 1, 2, etc.
   ```

3. **Проверьте threshold:**
   ```yaml
   openwakeword:
     threshold: 0.75  # Попробуйте 0.5 или 0.8
   ```

### Робот не слушает после wake word:

1. **Проверьте логи:** Ищите сообщения об ошибках
2. **Проверьте конфликты аудио:** Убедитесь, что PvRecorder и PyAudio не конфликтуют
3. **Проверьте STT:** Убедитесь, что Speech-to-Text работает

### Конфликты с аудио:

Wake word использует **PvRecorder**, а обычное прослушивание использует **PyAudio**. Они могут конфликтовать:

```python
# В коде есть логика остановки wake word детектора
# перед началом обычного прослушивания
await self.wake_word_detector.stop_listening()
await asyncio.sleep(0.2)  # Пауза для стабилизации
await self._process_command()  # Прослушивание команды
```

## 🎛️ Настройка параметров

### Основные параметры:

```yaml
openwakeword:
  threshold: 0.75          # Чувствительность (0.5-0.9)
  consecutive_frames: 3    # Сколько кадров подряд для обнаружения
  debounce_seconds: 1.2    # Пауза между обнаружениями
  frame_length: 1280       # Размер аудио фрейма
  device_index: 0          # Индекс аудио устройства
```

### Режимы работы:

- **onnx**: Кастомная ONNX модель (рекомендуется)
- **custom**: Классификатор sklearn
- **pretrained**: Готовые модели (alexa, hey_jarvis)

## 🔄 Переключение на другие wake words

### Для использования "Alexa":

```yaml

  models: ["alexa"]
  threshold: 0.6
```

### Для использования "Hey Jarvis":


## 🚀 Оптимизация

### Для лучшей работы:

1. **Качественный микрофон** близко к источнику звука
2. **Тихая среда** без фонового шума
3. **Правильная настройка threshold** (не слишком чувствительная)
4. **Достаточная пауза** между командами

### Производительность:

- **ONNX режим** работает быстрее кастомного классификатора
- **Consecutive frames = 3** баланс между скоростью и точностью
- **Debounce seconds = 1.2** предотвращает множественные срабатывания
